# URL、href与src

## **1.1 URL的概念**

统一资源定位符（或称统一资源定位器/定位地址、URL地址等，英语：**Uniform Resource Locator**，常缩写为URL），有时也被俗称 网址，是因特网上标准的资源的地址（Address）。

## **1.2 URL的格式**
    协议类型:[//服务器地址[:端口号]][/资源层级UNIX文件路径]文件名?查询

```py linenums="1"
scheme://host.domain:port/path/filename
```

+ （1）**scheme** - 定义因特网服务的类型，即**协议**。最常见的类型是 http

!!! 常见的scheme
    · **http**——超文本传输协议资源（不加密） · **https**——用安全套接字层传送的超文本传输协议（加密）

    · **ftp**——文件传输协议

    · **ldap**——轻型目录访问协议搜索

    · **file**——当地电脑或网上分享的文件

    · **telnet**——Telnet协议

+ （2）**host** - 定义域主机（http 的默认主机是 www）

+ （3）**domain** - 定义因特网域名，比如 picklerick422.github.io

+ （4）**[:]+[port]** - 定义主机上的端口号（http 的默认端口号是 80） 

+ （5）**path** - 定义服务器上的路径（如果省略，则文档必须位于网站的根目录中）。 

+ （6）**filename** - 定义文档/资源的名称

## **1.3 绝对与相对URL**

**绝对URL（absolute URL）**显示文件的完整路径，这意味着绝对URL本身所在的位置与被引用的实际文件的位置 **无关**。

!!! tip
    绝对路径要写成：`C:\\...\\`

    或者 `C:/.../`

    因为有转义字符，所以要注意

**相对URL（relative URL）**以包含URL本身的文件夹的位置为 **参考点**，描述目标文件夹的位置。

!!! 相对url中
       "**.**":代表目前所在的目录，相对路径。如：`<ahref="./abc">文本</a>或<img src="./abc" />`

       "**..**"：代表上一层目录，相对路径。如：`<ahref="../abc">文本</a>或<img src="../abc" />`

       "**../../**"：代表的是上一层目录的上一层目录，相对路径。如：`<imgsrc="../../abc" />`

       "**/**"：代表根目录，绝对路径。如：`<ahref="/abc">文本</a>或<img src="/abc" />`

       "**D:/abc/**"：代表根目录，绝对路径。

!!! tip
    **有意思的小故事**：码python代码，被干崩溃了，一串相对路径老是说“No such file or directory”，就很莫名其妙，明明路径写的很对啊QAQ

    后来查了很多大佬的博客才知道，这是**终端运行**的问题。<u>由于我们使用终端或者cmd运行，当我们运行的时候，默认路径是在python的默认路径，所以找不到你的文件。而在其他IDE上运行的默认路径就是文件所在路径，所以就可以正常生效。</u>实在是抽象的很，我就说老师在jupyter上的代码跑起来就没问题，我在vscode上用绝对路径也没问题，相对路径就不行，还是太细了。

## **2.1 href的概念**

**href (Hypertext Reference)**指定网络资源的位置，从而在当前元素或者当前文档和由当前属性定义的需要的锚点或资源之间定义一个链接或者关系。

!!! note
    href 目的不是为了引用资源，而是为了建立联系，让当前标签能够链接到目标地址。

## **3 src的概念**

source（缩写），指向外部资源的位置，指向的内容将会应用到文档中当前标签所在位置。

## **4 href与src的区别**

**请求资源类型不同**

    （1）href 指向网络资源所在位置，建立和当前元素（锚点）或当前文档（链接）之间的联系。

    （2）在请求 src 资源时会将其指向的资源下载并应用到文档中，比如 JavaScript 脚本，img 图片；

**浏览器解析方式不同**

    （1）若在文档中添加<link href="style.css" rel="stylesheet" /> ，
    
    浏览器会识别该文档为 CSS 文件（样式表），就会并行下载资源并且不会停止对当前文档的处理。
    
    这也是为什么建议使用 link 方式加载 CSS，而不是使用 @import 方式。

    （2）当浏览器解析到 ，会暂停其他资源的下载和处理，直到将该资源加载、编译、执行完毕，图片和框架等也如此，
    
    类似于将所指向资源应用到当前内容。这也是为什么建议把 js 脚本放在底部而不是头部的原因。
